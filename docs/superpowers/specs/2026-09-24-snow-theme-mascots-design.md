# 雪地主題與吉祥物 設計

## Context

五個模式的功能都做完了。現在要加的是**美術主題**與**兩隻吉祥物**(小狐狸、白鼬)。

使用者提供了參考圖:兩張橫幅(冬天雪地、春天花草)與三張 Q 版小圖。參考圖是柔和插畫風(有漸層、有陰影、邊緣是軟的),跟現有網站的平塗粗描邊風**不同** —— 這個衝突在 grill 階段解決了:吉祥物改畫成現有平塗風,參考圖只當造型參考。

使用對象是國小生。零建置是硬性條件(沒有 package.json、沒有 node_modules、沒有 bundler),部署在 GitHub Pages。

## 已封閉的決策(grill 階段確定,實作時不得重新討論)

| 決策 | 結論 |
|---|---|
| 主題數量 | **一套固定的雪地森林**。沒有切換、沒有設定、沒有季節變化、沒有任何持久化狀態 |
| 畫風 | 吉祥物改畫成**現有的平塗粗描邊風**,不是參考圖那種柔和插畫風。參考圖只當造型參考 |
| 雪地的範圍 | 雪地只是**舞台**。背景換成雪地,但卡片/按鈕維持暖米色 + 珊瑚紅;3D 物件維持現有識別色 |
| 3D 物件顏色 | **不得轉冷**。大亂鬥的隊伍紅綠藍、扭蛋的 12 色是**功能**不是裝飾 |
| 出現方式 | 兩隻**永遠成對**,不分開、不隨機 |
| 姿勢歸屬 | `pose` 屬於**這一對**,不屬於個別動物。每個姿勢是一張完整的雙人構圖 |
| 姿勢數量 | 五個:`idle` / `watch` / `cheer` / `aww` / `empty` |
| 待機 | 不能定格。呼吸常駐 + 每隔幾秒隨機插一個小動作 |
| 互動 | **不可點**(`pointer-events: none`),不做點擊互動 |
| 位置 | 五個模式統一在**左下角**常駐,約畫面高 12~15%(手機約 80~100px);首頁是放大版主視覺放在標題旁 |
| 首頁卡片 | 五張卡片的插圖**不動**,維持現有 CSS 圖案 |
| 背景組成 | 天空漸層 + 雪坡 + 淡遠景 + 20~30 片純 CSS transform 飄雪 |
| reduced-motion | 飄雪完全關閉(不產生節點,不是產生後隱藏) |
| 技術路線 | 一個共用模組 `shared/js/mascot.js`,**JS 注入行內 SVG** |
| 揭曉時 | 吉祥物**飛進揭曉區**,五個模式都接 |
| 排版 | 揭曉面板的排版**完全不知道吉祥物存在**。加或不加都長一樣 |
| 儲存 | **不新增任何 localStorage key**,五個模式現有的存檔格式一個位元都不動 |
| 建置 | 零建置維持不變 |

### 角色設定

- **白鼬**:生性溫潤,堅韌隨和
- **狐狸**:深情專一非常喜歡白鼬,孤傲強大,溫柔細緻
- 常見畫面:狐狸保護白鼬、白鼬窩在狐狸尾巴裡

### 五個姿勢的構圖

| pose | 時刻 | 構圖 |
|---|---|---|
| `idle` | 平常 | 白鼬窩在狐狸尾巴裡,狐狸盤坐半瞇眼守著 |
| `watch` | 演出進行中 | 兩隻一起抬頭盯著畫面中央;狐狸耳朵豎起,尾巴仍圈著白鼬 |
| `cheer` | 大獎、贏家出爐 | 白鼬整隻跳起來歡呼;**狐狸不跳,眼睛彎起來看著白鼬**、尾巴大力擺 |
| `aww` | 全部槓龜、平手 | 白鼬垂耳,**狐狸用尾巴把牠整個裹起來**輕拍 |
| `empty` | 抽完了 | 空箱子,白鼬趴在箱沿睡著,狐狸靠著箱子守夜 |

`cheer` 時狐狸看的是**白鼬不是獎品**。這是刻意的:「深情專一」在畫面上只能這樣表達 —— 如果狐狸也對獎品歡呼,牠就跟白鼬變成同一個角色,那個「孤傲,但對你溫柔」的反差就消失了。

## 確認過的 Model(實作若與此牴觸,是計畫的 bug —— 停下來反映,不要就地改模型)

**Entities**
- `MascotPair` — 一對吉祥物(狐狸 + 白鼬),全站唯一一對,每頁一個實例
- `Pose` — 五個值之一:`idle` / `watch` / `cheer` / `aww` / `empty`。屬於這一對,不屬於個別動物
- `Placement` — `corner`(左下角常駐)或 `reveal`(飛到某個錨點旁)
- `Anchor` — 每個模式提供的空的、不佔空間的定位錨點
- 雪地主題**不是 entity**,是寫死的 CSS

**Cardinality**
- `MascotPair` 1:1 `Pose`、1:1 `Placement`(同時只有一個姿勢、一個位置)
- 每個模式 **2 個** `Anchor`:一個給揭曉、一個給空狀態
- 狐狸和白鼬**不是獨立實體**,沒有各自的 pose 欄位 —— 牠們是同一張雙人構圖裡的兩個部位

> **模型修訂(brainstorming 階段追加)**:grill 當下確認的模型寫的是「每個模式 1 個 `RevealAnchor`」。
> 後來決定 `empty` 姿勢也要飛到空狀態面板旁,所以錨點從 1 個變 2 個,`RevealAnchor` 一般化為 `Anchor`。
> 這是使用者明確同意的修訂,**不是**實作偏離模型。

**Seen vs stored**
- 看到「兩隻在角落呼吸、偶爾翻身」→ **什麼都沒存**。`pose` 和 `placement` 都是當下畫面狀態,重整就回 `idle` / `corner`
- 看到「雪地 + 飄雪」→ 沒有主題欄位,寫死的 CSS
- 看到「牠們飛到獎項旁」→ 揭曉面板的排版**完全不知道吉祥物存在**,加不加都長一樣
- **localStorage 不新增任何 key**

**最可能做錯的四個(以下四句都是錯的)**

1. 「狐狸和白鼬各有自己的 pose,可以分別切換」 —— 錯。拆開會生出「狐狸在抱空氣」這種組合,而且兩隻會不同步
2. 「主題要存一個設定,之後好切換或依季節換」 —— 錯。一套固定的雪地,沒有切換、沒有設定、沒有持久化
3. 「吉祥物飛進揭曉區時,插進獎項面板的 DOM 裡跟著排版」 —— 錯。吉祥物**永遠不進入任何模式的 DOM**
4. 「雪地是全站換色」 —— 錯。雪地只是舞台

## 檔案結構

```
shared/css/theme-snow.css   雪地舞台:天空、雪坡、遠景、雪花的樣式
shared/js/snow.js           把雪花節點注入頁面(數量是常數)
shared/css/mascot.css       骨架的姿勢(五組 transform)、待機動畫、角落定位
shared/js/mascot.js         SVG 骨架 + pose/placement 狀態 + 待機排程 + 飛行
shared/css/tokens.css       只改 body 那段背景(米色圓點 → 雪地),其他 token 不碰
test/mascot.test.js         狀態機與待機排程
test/snow.test.js           雪花參數與 reduced-motion
```

每個模式的 HTML 只加:兩行 `<link>`、模組的 import、兩個空的錨點 `<div>`。

**為什麼雪和吉祥物分兩個模組**:它們唯一的共同點是「都是裝飾」。雪是靜態舞台,注入一次就不管了;吉祥物有狀態機、有排程、要跟五個模式接線。混在一起會變成一個什麼都做的 `decor.js`,以後想關掉雪也得動到吉祥物。

**為什麼雪要 JS 注入而不是寫在 HTML**:24 片 × 5 個頁面 = 120 行重複標記,而且每片要不同的起始位置/速度/大小。

**為什麼雪花是真的元素而不是 CSS 背景圖**:`transform` 跑在合成器上,不碰主執行緒也不觸發重繪;`background-position` 動畫會踩到 paint,在跑 WebGL 的那三個模式上比較危險。

## 雪地舞台

四層,由後到前:

| 層 | 做法 | 內容 |
|---|---|---|
| 天空 | `body` 的 linear-gradient | 淡藍 `#DCEBF7` → 接近地平線轉白 `#F3F8FC` |
| 遠景 | 內嵌 SVG data URI 當 background-image | 松樹剪影 + 小木屋,`#BCD2E4` 壓到 30% 不透明,貼畫面**上緣** |
| 雪坡 | 同一個 `body` background 的第三層 | 畫面下方兩三道起伏,白 `#FFFFFF` 配淡藍陰影 `#E8F1F8` |
| 雪花 | `shared/js/snow.js` 注入的 `<div>`,transform 動畫 | 固定定位的一層 |

前三層**全部在 `body` 的 `background` 裡,零 DOM、零額外請求**。遠景用 data URI 內嵌,不多一次網路往返(GitHub Pages 首次載入已經偏慢,不再加一筆)。

**雪花放在舞台「後面」,不是前面**,理由:

1. 小孩要讀的是獎項名稱和按鈕,雪花飄過文字會扣分
2. 三個 3D canvas 是**透明**的 —— 雪花在後面一樣會從 canvas 透出來,看起來就是「雪下在場景裡」。等於免費拿到前景效果而沒有前景的代價

**雪花參數**:`FLAKES = 24`(常數,取自決策裡「20~30 片」這個區間的中間值)、2~6px、落下 8~18 秒、左右飄移靠第二個 transform。`prefers-reduced-motion` 時**完全不注入節點**。

**顏色取捨**:舞台轉冷之後,卡片和按鈕維持暖米色 `#FFF7EC` + 珊瑚紅 —— 暖色壓在冷色上是對比最強的組合。文字 `--ink #574239` 是深咖啡,壓在淡藍上對比依然足夠。

## 吉祥物模組

### 最關鍵的結構決定

**吉祥物是 `<body>` 底下一個 `position: fixed` 的獨立層,從頭到尾不進入任何模式的 DOM。**

錨點只當**座標來源**(讀 `getBoundingClientRect()`),不當父容器。這讓「揭曉面板的排版完全不知道吉祥物存在」從一個**約定**變成**結構上不可能違反** —— 沒有人能不小心把吉祥物插進面板裡,因為它根本不在那棵樹上。

已確認:五個揭曉容器都是普通的 `div` / `section`,不是 `<dialog>`。如果是 `showModal()` 的 dialog,它會進 top layer,外面的 fixed 層**不可能**疊在它上面,整個做法要重來。設定面板才是 `<dialog>`,而吉祥物不需要蓋過設定面板。

### 骨架(做法 C:四個姿勢共用骨架,`empty` 獨立一張)

`idle` / `watch` / `cheer` / `aww` 是同一個場景的四個瞬間 —— 都是「狐狸坐著、白鼬在尾巴附近」,差別只在頭的角度、耳朵、白鼬的位置和表情。這四個共用一套骨架,切換靠 CSS transition **滑過去**,不是換圖。

`empty` 是完全不同的場景(有箱子、白鼬睡著、構圖不同),而且出現時機也不同(不是「反應」,是「狀態」),獨立畫一張。

選 C 的理由:那四個姿勢會在同一次抽獎裡連續切換(`watch` → `cheer` → `idle`),**它們之間的過渡就是小孩會看到的東西**。`empty` 不跟其他姿勢連續切換,獨立畫一張反而更自由。

**骨架零件**:
- 狐狸:尾巴、身體、頭、左右耳、眼、鼻口
- 白鼬:身體、頭、左右耳、眼、黑尾尖

**姿勢怎麼表達**:根元素掛一個 class(`.mascots--cheer`),CSS 裡定義每個零件在該姿勢的 `transform`。切換 = 換 class,`transition` 自動補出過渡。美術資料住在 CSS 不在 JS,可以直接在 devtools 裡調到好看。

**待機**:呼吸是常駐 keyframes;小動作是每 4~9 秒隨機掛一個 class(`--yawn` / `--ear` / `--nuzzle`),放完拿掉。

### 首頁的放大版不是第三種 placement

首頁的兩隻要大、要在標題旁邊,但那**不是新的 `Placement` 值**。`placement` 只有 `corner` 和 `reveal` 兩個值;首頁走的還是 `corner`,只是在根元素多掛一個 `.mascots--home` 的修飾 class,由 CSS 改尺寸與位置。

理由:首頁的兩隻不會飛、不會換姿勢(永遠是 `idle` + 待機小動作),行為跟其他頁完全一樣,差別純粹是外觀。把它做成第三種狀態會讓狀態機多一個只有一頁用得到的分支。

### API

```js
const mascots = mountMascots();        // pose=idle, placement=corner
// 首頁:mountMascots({ home: true }) —— 只影響外觀,不影響狀態機
mascots.setPose('cheer');              // 只換姿勢,位置不動
mascots.flyTo(el, { pose: 'cheer' });  // 飛到 el 旁 + 換姿勢
mascots.home();                        // 飛回角落,回 idle
```

### 兩個已經踩過的坑,要先防

1. **分頁切到背景時計時器會被節流、動畫會停**。飛行用 CSS transition + `transitionend`,而且**一定要配 setTimeout 後備** —— 扭蛋機的 `tween` 就是漏了這個,演出永遠停在半路。
2. **錨點被 `hidden` 時 rect 是 0** → 直接退回角落,不要飛到左上角 (0,0)。

## 五個模式接哪些時刻

| 模式 | `watch` | 飛過去 + `cheer` | `aww` | `empty` |
|---|---|---|---|---|
| 扭蛋機 | 按下「轉!」開始演出 | SSR / UR 開出來時飛到 `#prizeCard` | — | 機器空了 |
| 立體扭蛋機 | 點下某顆蛋 | SSR / UR 飛到 `#prizeCard` | — | 桌上抽完了 |
| 一番賞 | 拿起籤紙、等使用者決定撕不撕 | A/B 賞或**最後一抽賞**飛到 `#overlay` | — | 全部抽完 |
| 阿彌陀籤 | 開跑到跑完 | `#results` 出現且**有人中獎** | 全部都是銘謝惠顧 | 沒有人或沒有獎 |
| 大亂鬥 | 開打到分出勝負 | 贏家出爐,飛到 `#winner` | 平手 / 全滅 | 沒有隊伍 |

**一個原則:每個模式都有「飛過去」的時刻,但不是每次結果都飛。** 只有真正值得的結果才飛 —— 如果每抽一次牠們就衝過來一次,那個動作三次之後就不特別了,而且會變成干擾。普通結果就在角落換個表情。

所以 `aww` 的用法很窄:只給阿彌陀籤「全部槓龜」和大亂鬥「平手」。**扭蛋機抽到 N 賞不算失敗** —— 那是最常見的結果,每次都讓白鼬垂耳朵,小孩會覺得被吉祥物嫌棄。

`empty` 飛到空狀態面板旁(每個模式的第二個錨點)。理由:「抽完了」是五張裡唯一一張**有敘事**的圖(睡著的白鼬、守夜的狐狸),塞在角落 80px 大小是浪費;而空狀態面板本來就是畫面上最空的地方。空狀態也不像揭曉那樣稍縱即逝,小孩會盯著看比較久。

# 修訂一(2026-09-24):素材從手刻 SVG 改為生成圖

## 為什麼改

原設計的「吉祥物改畫成現有平塗粗描邊風、由 JS 注入行內 SVG 骨架」實作了三輪
(v1 `aad0c4e` / v2 `cd9eda9` / v3 `ed488f1`),使用者三次都判定不合格,最後一次的原話是
「還是很醜 跟我傳的圖片還是差很多」。

**根本原因不是技巧,是媒材。** 角色的討喜來自上千個微小的曲線決定,而手寫 SVG path
是由看不到即時畫面的模型一條一條刻出來的 —— 那正是這種做法最弱的地方。
grill 當時「吉祥物改畫成平塗風」的決定,前提是「替代方案是我手畫」;
使用者本機有 ComfyUI 之後,那個前提就不成立了。

## 改了什麼

| 項目 | 原設計 | 修訂後 |
|---|---|---|
| 素材 | JS 注入的行內 SVG 骨架 | **生成的 WebP 圖**,放在 `shared/img/mascot/` |
| 姿勢切換 | 換 class,CSS transform 補間 | **換 `<img>` 的 src**,配淡入淡出 |
| 局部動畫 | 每個零件各自 transform | **不做**(見下方裁決) |
| 待機 | 呼吸 + 隨機小動作 | 呼吸(整體 `scaleY`)+ 偶爾切到 `doze` 那張 |

## 沒有改的(確認過的 Model 完全存活)

- `MascotPair` / `Pose` / `Placement` / `Anchor` 四個 entity,語意一字未改
- **`Pose` 仍然是五個值**:`idle` / `watch` / `cheer` / `aww` / `empty`。
  多出來的 `doze.webp` **不是第六個 pose**,它是 `idle` 的一個待機變化,
  跟「打哈欠」「抖耳朵」是同一類東西
- pose 仍然屬於**這一對**,不屬於個別動物 —— 這一點反而更牢固了,
  因為一張圖裡本來就只有一個構圖,連拆開的可能性都沒有
- 吉祥物仍然**永遠不進入任何模式的 DOM**,錨點仍然只當座標來源
- 不新增任何 localStorage key;零建置不變

## 素材

`shared/img/mascot/` 六個檔,560px 高,WebP:
`idle` / `watch` / `cheer` / `aww` / `empty` / `doze`,合計約 278 KB。

**載入策略(新增的要求)**:只有 `idle` 在首屏載入(約 45 KB),其餘五張延後到
第一次要用到時才抓。六張一起預載會讓首屏成本變成 278 KB —— 這個站的首屏延遲
本來就被抱怨過,不能再加一筆。

## 產生素材的流程(要能重現)

使用者本機 ComfyUI(RTX 5070 Ti),模型 `z_image_turbo_bf16`。關鍵設定:

- `CLIPLoader` 的 `type` 必須是 **`lumina2`**(選項清單裡沒有 `z_image`,猜不到)
- text encoder `qwen_3_4b.safetensors`、VAE `ae.safetensors`
- `ModelSamplingAuraFlow` shift 3.0、`KSampler` cfg **1.0**、`res_multistep`、`simple`、10~12 步

**試過但不可行的兩條路,不要再試**:

1. `TextEncodeZImageOmni` 餵參考圖 → KSampler 丟 shape 錯誤。裝的是 turbo 純文生圖權重,
   不是 Omni 編輯權重
2. 「六格分鏡一次生成」→ turbo 模型跟隨力不足,只畫 4 格而且白鼬全變成狐狸

可行的是:**一張一個姿勢**,共用同一段角色鎖定敘述 + 固定 seed。

去背在**本機**用 PIL 做,不用 ComfyUI(那台沒裝去背模型):
從四個角落泛洪填充、容差 95。用泛洪而不是全域色鍵,是因為角色身上的口鼻和胸口
也是米色,但它們與邊界不連通,所以不會被打出洞。

## 這次修訂新增的裁決

- **眨眼不做**。`idle` 與 `idle-blink` 不是同一張只差眼睛(狐狸大小位置都不同),
  直接切換是「整隻跳一下」。改為把那張當 `doze`(打瞌睡)的待機變化。
  要真正的眨眼,得用 inpaint 從 `idle` 原圖產生對齊的閉眼疊圖,列為日後選項。
- **不切部位做骨架**。角落顯示只有 80~100px,尾巴擺動的位移約 3px,看不見;
  而每切一層都要 inpaint 補被遮擋的洞,六個姿勢乘上去成本很高。
  首頁(約 260px)那個尺寸值得做,但等接線上線後再評估。
